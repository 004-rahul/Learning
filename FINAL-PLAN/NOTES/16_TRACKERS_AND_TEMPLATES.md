## S11 — 11_Trackers_and_Templates

Full source content: [Study-Plan/11_Trackers_and_Templates.docx](../SOURCE_LIBRARY/Study-Plan/11_Trackers_and_Templates.docx). Original wording is retained below. For conflicting statements, use the visible correction and the current execution plan.


<a id="S11-B0001"></a>

Trackers and Templates

<a id="S11-B0002"></a>

Document 11 - Copy these into your working documents. Use them daily.

<a id="S11-B0003"></a>

### How to set this up

<a id="S11-B0004"></a>

Keep it simple. One spreadsheet with several tabs, plus one notes document. Do not spend a weekend building a system - the system is not the work.

<a id="S11-B0005"></a>

| Artefact | Where it lives |
| --- | --- |
| Master Notes | One document, one page per concept, six-question frame |
| Weak List | Spreadsheet tab. The most important tab |
| DSA Log | Spreadsheet tab, one row per problem |
| Spaced Review Tracker | Spreadsheet tab, driven by dates |
| Work Journal | Plain text file, one line per working day, append only |
| STAR Story Bank | One document, one page per story |
| Interview Analysis Log | Spreadsheet tab, from Month 6 |
| Application Tracker | Spreadsheet tab, from Month 6 |

<a id="S11-B0006"></a>

### Template 1 - Master Notes (one page per concept)

<a id="S11-B0007"></a>

| Field | Fill in |
| --- | --- |
| Concept |  |
| Date learned |  |
| What is it? | One sentence, junior-developer level |
| Why does it exist? | What problem forced its invention |
| Mental model | The analogy or picture you use |
| How does it work internally? | The mechanism. This is the interview level |
| Example | Smallest code or scenario that demonstrates it |
| Real use from my work | Casepoint, Vision, Zibma, or a project. Always fill this in |
| Common mistakes | What people get wrong, including what you got wrong |
| Trade-offs | What it costs. Nothing is free |
| When would I NOT use it? | The question that proves depth |
| Interview questions on this | Three you would expect |
| My own explanation | Written from memory, notes closed |
| Review dates | D1 __ / D3 __ / D7 __ / D14 __ / D30 __ |

<a id="S11-B0008"></a>

Keep each page short. A page that takes 40 minutes to write and is never reread is worse than a page that takes 10 minutes and gets retrieved five times.

<a id="S11-B0009"></a>

### Template 2 - Weak List

<a id="S11-B0010"></a>

Every failure to recall, explain or solve goes here immediately. This list drives Friday sessions and Sunday tests.

<a id="S11-B0011"></a>

| Item | Added | Source | Attempt 1 | Attempt 2 | Cleared |
| --- | --- | --- | --- | --- | --- |
| Why .Result deadlocks | 12 Sep | Weekly test | Failed | Passed |  |
| Consistent hashing | 3 Oct | Recall | Failed |  |  |
| Course Schedule II | 8 Oct | DSA | Failed | Failed |  |

<a id="S11-B0012"></a>

Rules: an item leaves the list only after two consecutive successful recalls at least seven days apart. If the list has not grown in two weeks, you are not testing yourself hard enough.

<a id="S11-B0013"></a>

### Template 3 - DSA log

<a id="S11-B0014"></a>

| Problem | Diff | Pattern | Brute O | Opt O | Key insight | Variation | Re-solve |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Two Sum | E | Hashing | O(n^2) | O(n) | Complement lookup in a map | If sorted, two pointers | D1 D3 D7 |
| Course Schedule | M | Topo sort | - | O(V+E) | Cycle detection via in-degree | Return the order itself | D1 D3 |

<a id="S11-B0015"></a>

The "key insight" column is the one that matters. If you cannot write it in one sentence, you have not understood the problem - you have only made it pass.
